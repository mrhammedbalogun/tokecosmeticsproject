{% comment %} The shell every Toke Cosmetics email renders inside. ── THE BRAND, IN THE TERMS EMAIL CAN ACTUALLY EXPRESS ────────────────────────────── Tokens are the storefront's (`storefront/src/app/globals.css`), used literally so an order confirmation and the page it was ordered from look like one company: beige #f1eae0 the page behind the card surface #ffffff the card line #e7e2d8 hairlines ink #1a1a1a body text ink-soft#6b6862 captions, footer accent #1c7a3e Toke forest green — the top rule, buttons, links gold #c9a227 the eyebrow rule (used sparingly, as on the site) The site's display face is Playfair Display and its body face Inter. NEITHER is used here: a webfont needs an @font-face fetch that Outlook, Gmail's web client and Yahoo all refuse, so half the recipients would get the fallback anyway and the mail would look like two different designs depending on the inbox. Georgia (the closest ubiquitous serif to Playfair) and Arial stand in, and every reader gets the same thing. ── WHY THE MARKUP LOOKS LIKE 2003 ────────────────────────────────────────────────── Nested tables, inline styles, fixed widths. Outlook 2016+ renders with Word's engine: no flexbox, no grid, no float, no `max-width`, no `border-radius`, no `background-image`, and it drops most of a {% comment %} Preview text. Hidden in the body, read by the inbox list. The run of zero-width joiners after it is the standard padding trick: without it the client keeps scraping real content to fill its preview line and appends the header's alt text. {% endcomment %}

{% comment %} Everything below the white card: the social row, the shop links, and the line that tells the reader why this landed in their inbox. It sits on the beige page background rather than inside the card on purpose — the card is the message, this is the letterhead's reverse. Text is `ink-soft` (#6b6862) at 12–13px so it reads as secondary without dropping below the ~11px where phones start to render it unreadably small. Two hooks for the templates: footer_note overrides "why you got this". The default is written for a CUSTOMER; staff and ops alerts say something else entirely, and a wrong line here is how somebody concludes an internal alert is marketing and unsubscribes from an order feed. socials set to an empty block to drop the social row (all staff/ops mail does). NO UNSUBSCRIBE LINK, deliberately: every template in this directory is transactional — an order, a payout, a security notice, a sign-in code. There is no marketing mail in this system yet. The day one is added it needs its own base template with a real one-click unsubscribe (List-Unsubscribe header included), not a link bolted on here that would silently offer to switch off order confirmations. {% endcomment %}
