{% comment %} The customer's line-item table: picture, description, line total. ── EMAIL HTML IS NOT WEB HTML, and every choice below is a workaround ────────────── * **Nested , not flexbox or float.** Outlook 2016+ renders with Word's engine, which supports neither. A table cell is the only layout primitive that works everywhere. * **Explicit width AND height on every , plus the same values in the style attribute.** Outlook ignores CSS dimensions and honours the attributes; Gmail does the reverse. Without both, a blocked or slow image collapses the row and the layout jumps. * **`display:block` on the image** kills the descender gap under inline images in Gmail/Outlook that otherwise shows as a stray line of whitespace. * **Alt text on every image, and it is the product name.** Most clients block remote images until the reader clicks "show images" — Gmail proxies them, Outlook blocks by default — so for a large share of readers the alt string IS the picture. It must therefore say which product the row is, never "product photo". * **The picture cell is fixed-width and the row survives without it.** `{% if %}` around the rather than around the cell, so a line with no image (a deleted product, or any order placed before checkout started snapshotting images) keeps its column alignment instead of shifting the whole table left. * **No `background-image`** anywhere: Outlook drops it silently. * **`object-fit:cover` is a belt, not the fix.** Word's engine ignores it, so a non-square source forced into a square box there is DISTORTED, not cropped.
