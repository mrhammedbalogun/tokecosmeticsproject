# Plan-02 VPS Provision — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the Django API at `https://api.tokecosmetics.com` from a Docker stack on the Namecheap VPS, so the already-deployed Vercel storefront at `https://next.tokecosmetics.com` has a backend — without disturbing the live, revenue-generating WordPress stores on the same box.

**Architecture:** Five containers under Docker Compose in `/opt/tokecosmetics`, every one bound to `127.0.0.1` so nothing new is publicly reachable. The existing Apache (which owns :80/:443) proxies `api.tokecosmetics.com` to `127.0.0.1:8001` via a **separately included** conf file — Webuzo's own `webuzoVH.conf` is never edited. Public TLS is Cloudflare's; origin TLS is a Cloudflare Origin CA certificate.

**Tech Stack:** Docker Engine + compose plugin, `postgres:16-alpine`, `redis:7-alpine`, gunicorn on `python:3.12-slim`, Celery worker + beat, Apache `mod_proxy_http`, Cloudflare (DNS/proxy/Origin CA), GitHub Actions for deploys.

### ⚠️ The one thing that could take the live store down

`Include etc/conf.d/*.conf` loads **alphabetically**, and in Apache the **first** `<VirtualHost>` for a given address is the *default* for it — the one that catches requests matching no other `ServerName`. `webuzo.conf` and `webuzoVH.conf` both start with `w`. A file named `api.conf` would load **first** and silently become the default vhost for the live stores' IP:port, sending unmatched WordPress traffic to Django.

**The file must therefore be named `zz-api.conf`.** This is not cosmetic. Task 6 verifies ordering explicitly before Apache is ever reloaded.

### What is NOT in this stage

- **No Meilisearch container.** `apps/search/backends.py::get_backend()` returns `PostgresSearchBackend()` unconditionally; Meilisearch is parked for "Plan-07b". Search runs on `pg_trgm` (created by `catalog/migrations/0004_product_name_trgm.py`). Saves 512 MB and one service. The master guide's six-service list is superseded here.
- **No live payment keys.** Paystack stays on its **test** key. Going live is Plan-27.
- **No DNS cutover.** `tokecosmetics.com` keeps serving WordPress.

`libpango-1.0-0` and `libpangoft2-1.0-0` are not optional. WeasyPrint is a *binding* over Pango/cairo — `pip install weasyprint` succeeds without them and then `ImportError`s at runtime, so every invoice download 500s. This is recorded in the master guide under Plan-02 item 3. `worker` doesn't need them but shares the image.

```dockerfile
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

# libpango*: WeasyPrint native deps — invoices 500 at RUNTIME without them, not at build.
# libpq5: psycopg runtime.  curl: container healthchecks.
RUN apt-get update && apt-get install -y --no-install-recommends \
        libpango-1.0-0 \
        libpangoft2-1.0-0 \
        libpq5 \
        curl \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Dependency layer first so code edits don't reinstall the world.
COPY pyproject.toml uv.lock* /app/
RUN pip install uv && uv pip install --system --requirement pyproject.toml

COPY . /app/

RUN adduser --disabled-password --gecos "" --uid 10001 app \
    && mkdir -p /app/staticfiles /app/media \
    && chown -R app:app /app
USER app

EXPOSE 8000
CMD ["gunicorn", "config.wsgi:application", \
     "--bind", "0.0.0.0:8000", \
     "--workers", "3", \
     "--timeout", "60", \
     "--access-logfile", "-", \
     "--error-logfile", "-"]
```

## Task 2: Production compose file

**Files:**
- Create: `infra/docker-compose.prod.yml`

- [x] **Step 1: Write the compose file**

Every published port is `127.0.0.1:`-prefixed. That is a security control, not tidiness: Docker writes its own iptables rules that bypass UFW, so a bare `"8001:8000"` would expose Django to the internet regardless of the firewall.

```yaml
# Production stack. Nothing here is publicly reachable — Apache proxies to web:8001.
# Total budget ~2.6 GB against ~4 GB available; the live WordPress stack shares this box.
name: tokecosmetics

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - /opt/tokecosmetics/data/pg:/var/lib/postgresql/data
    ports:
      - "127.0.0.1:5433:5432"
    mem_limit: 1g
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER}"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: redis-server --maxmemory 200mb --maxmemory-policy allkeys-lru --save ""
    ports:
      - "127.0.0.1:6380:6379"
    mem_limit: 256m

  web:
    build:
      context: ../backend
      dockerfile: Dockerfile
    image: toke-api:latest
    restart: unless-stopped
    env_file: /opt/tokecosmetics/.env.prod
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "127.0.0.1:8001:8000"
    volumes:
      - /opt/tokecosmetics/data/static:/app/staticfiles
      - /opt/tokecosmetics/data/media:/app/media
    mem_limit: 768m
    healthcheck:
      test: ["CMD", "curl", "-fsS", "http://localhost:8000/healthz/"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 30s

  worker:
    image: toke-api:latest
    restart: unless-stopped
    env_file: /opt/tokecosmetics/.env.prod
    command: celery -A config worker -c 2 --loglevel=info
    depends_on:
      - redis
      - postgres
    volumes:
      - /opt/tokecosmetics/data/media:/app/media
    mem_limit: 512m

  beat:
    image: toke-api:latest
    restart: unless-stopped
    env_file: /opt/tokecosmetics/.env.prod
    command: celery -A config beat --loglevel=info
    depends_on:
      - redis
    mem_limit: 128m
```

## Task 6: Expose `api.tokecosmetics.com` — ✅ DONE 2026-07-25

> **This task edits Apache config on the live web server.** Back up first, verify ordering, `configtest` before every reload.

### Deviations from the plan as written

**1. Step 3's `Require ip <HAMMED_IP>` was wrong and is now `Require all denied`.**
This vhost only ever sees Cloudflare edge addresses as the client, and `httpd -M` confirms
mod_remoteip is not loaded, so the real client IP cannot be recovered for authorisation.
`Require ip` would have returned 403 to every request, Hammed's included, with no log line
explaining it. His IP is also dynamic (shared house wifi). The admin is denied at the edge
until an access route is chosen — see "Django admin access" in `docs/runbooks/vps-stack.md`.

**2. Step 7's local verification used the wrong address.**
The plan had `curl -H "Host: api.tokecosmetics.com" https://127.0.0.1/healthz/`. The vhost is
bound to `203.161.38.201:443`, so a connection to `127.0.0.1:443` never matches it and falls
through to the global default vhost — a passing result would have proved nothing. Verified
with `curl --resolve api.tokecosmetics.com:443:203.161.38.201` instead, which hits the real
listener with the correct SNI and Host.

**3. Added an origin lock the plan did not have (approved by Hammed 2026-07-25).**
Before this, `curl --resolve api.tokecosmetics.com:443:203.161.38.201 https://api.tokecosmetics.com/healthz/`
returned 200 **from outside the network**. The origin IP is public knowledge because the
WordPress stores share it, so the entire API was addressable without Cloudflare's WAF or
rate limiting — and any future Cloudflare Access policy would have been bypassable the
same way. `<Location />` now allows only Cloudflare's published ranges (15 IPv4 + 7 IPv6,
fetched 2026-07-25), plus `127.0.0.1` and `203.161.38.201`. The second is needed because an
on-box `--resolve` check presents the box's public address as its source, not loopback;
without it every on-box diagnostic and the Task 9 deploy smoke test would 403.

> **Maintenance:** Cloudflare's ranges change rarely but they do change. If the API starts
> returning 403 for no apparent reason, re-fetch `https://www.cloudflare.com/ips-v4` and

- [x] **Step 1: Write `infra/deploy/backup.sh`**

```bash
#!/usr/bin/env bash
# Nightly Postgres dump -> local (14 days) -> S3. Run by cron as root.
set -euo pipefail

BACKUP_DIR=/opt/tokecosmetics/backups
STAMP=$(date +%Y%m%d-%H%M%S)
FILE="$BACKUP_DIR/toke-$STAMP.sql.gz"

set -a; . /opt/tokecosmetics/.env.prod; set +a

mkdir -p "$BACKUP_DIR"
docker compose -p tokecosmetics exec -T postgres \
    pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" | gzip > "$FILE"

# A dump that gzips to almost nothing is a failed dump, not a small database.
SIZE=$(stat -c%s "$FILE")
if [ "$SIZE" -lt 10000 ]; then
    echo "FATAL: dump is only ${SIZE} bytes — refusing to upload or rotate" >&2
    exit 1
fi

aws s3 cp "$FILE" "s3://${AWS_STORAGE_BUCKET_NAME}/backups/postgres/" --only-show-errors

find "$BACKUP_DIR" -name 'toke-*.sql.gz' -mtime +14 -delete
echo "backup ok: $FILE ($SIZE bytes)"
```

The size check matters: the classic backup failure is a script that dumps nothing every night for six months and rotates the good copies away.

- [x] **Step 2: Write `infra/deploy/restore.sh`**

```bash
#!/usr/bin/env bash
# Restore a dump into a SCRATCH database. Never touches the live one.
# Usage: restore.sh /opt/tokecosmetics/backups/toke-YYYYmmdd-HHMMSS.sql.gz [scratch_db]
set -euo pipefail

DUMP=${1:?usage: restore.sh <dump.sql.gz> [scratch_db]}
SCRATCH=${2:-toke_restore_test}

set -a; . /opt/tokecosmetics/.env.prod; set +a

if [ "$SCRATCH" = "$POSTGRES_DB" ]; then
    echo "FATAL: refusing to restore over the live database" >&2
    exit 1
fi

docker compose -p tokecosmetics exec -T postgres psql -U "$POSTGRES_USER" -d postgres \
    -c "DROP DATABASE IF EXISTS $SCRATCH" -c "CREATE DATABASE $SCRATCH"
gunzip -c "$DUMP" | docker compose -p tokecosmetics exec -T postgres \
    psql -U "$POSTGRES_USER" -d "$SCRATCH" -q
docker compose -p tokecosmetics exec -T postgres psql -U "$POSTGRES_USER" -d "$SCRATCH" \
    -c "SELECT count(*) AS orders FROM orders_order;"
echo "restored into $SCRATCH"
```
